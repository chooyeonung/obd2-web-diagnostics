# 벤치 검증 절차서 (부품 도착 후)

목표: **차량에 연결하기 전에** 전원부·통신·펌웨어를 단계별로 검증한다.
각 단계는 이전 단계 통과가 전제. 실패 시 다음 단계로 넘어가지 말 것.

## 준비물

- 주문 부품 일체 + 만능기판/점퍼선 + 인두
- 12V 어댑터 (1A 이상) — 차량 대신 벤치 전원
- 멀티미터

## 0단계 — 부품 하차 검사

- [ ] SN65HVD230 모듈 2개: 보드에서 **120Ω(R2) 저항 위치 확인 후 제거** (인두로 가열해 밀어냄)
- [ ] LM2596: 외관 확인 (트리머 있는 가변형인지)
- [ ] P6KE24A: 밴드(캐소드) 방향 표시 확인

## 1단계 — 전원부 단독 (ESP32 연결 금지)

```
12V 어댑터(+) ─ 폴리스위치 ─ SS34(밴드가 LM2596 쪽) ─┬─ LM2596 IN+
                                          P6KE24A(밴드가 + 쪽) ─┤
12V 어댑터(-) ──────────────────────────────────┴─ LM2596 IN-
```

- [ ] LM2596 출력 무부하 전압 측정 → 트리머 돌려 **5.0V 조정** (기본값이 높게 옴)
- [ ] 10분 방치 후 발열 확인 (미지근한 수준이어야 정상)
- [ ] 어댑터 극성 반대로 연결 → 출력 0V 확인 (SS34 역접속 보호 동작)

## 2단계 — ESP32 단독 (USB 전원)

- [ ] USB-C로 PC 연결 → 부팅 확인
- [ ] `cd firmware && idf.py set-target esp32s3 && idf.py build flash monitor`
- [ ] 로그에 `SoftAP started`, `HTTP/WS server started` 확인
- [ ] 폰/PC로 WiFi `OBD2-DIAG` (pw `obd12345`) 접속 → `http://192.168.4.1/` 테스트 콘솔
- [ ] 콘솔에서 `ATZ` → `ELM327 v1.5 (OBD2-DIY)` 응답
- [ ] `010C` → `NO DATA` (CAN 미연결이므로 정상 — 타임아웃 경로 검증)

## 3단계 — 전원부 + ESP32 결합

- [ ] 1단계 전원부 출력(5.0V) → ESP32 **5V(VIN)** 핀 (USB 분리 상태)
- [ ] 12V 인가 → 부팅·WiFi·콘솔 재확인
- [ ] 12V 전원 전류 측정 (WiFi 활성 기준 대략 50~150mA 수준이면 정상)

## 4단계 — CAN 트랜시버 결선

```
ESP32 GPIO4 → SN65HVD230 D    ESP32 3V3 → VCC
ESP32 GPIO5 → SN65HVD230 R    ESP32 GND → GND
```

- [ ] 3V3 전압 확인, 콘솔 `ATZ` 재확인 (트랜시버 연결 후에도 부팅 정상)
- [ ] (선택) 두 번째 SN65HVD230 + USB-CAN 분석기가 있으면 루프백 응답 테스트

## 5단계 — 실차 연결

- [ ] OBD 커넥터 배선: 4/5(GND), 6(CAN-H), 14(CAN-L), 16(+12V→전원부 입력)
- [ ] **시동 OFF, 키 ON(ACC)** 상태에서 먼저 연결 → 콘솔 `ATZ` 확인
- [ ] `0100` → `41 00 ...` 응답 = 차량과 CAN 통신 성공 🎉
- [ ] `010C`(RPM), `0105`(냉각수온), `0902`(VIN) 확인
- [ ] 시동 걸고 RPM 실시간 변화 확인
- [ ] 웹앱(로컬 dotnet run)에서 "자작 보드 (WiFi)" 모드 → `ws://192.168.4.1/ws` 연결 → 대시보드 동작

## 문제 발생 시

| 증상 | 우선 확인 |
|---|---|
| `0100`에 NO DATA | 120Ω 제거 여부 / CANH·CANL 뒤바뀜 / GND 공통 여부 |
| 간헐적 응답 | 배선 길이(짧게), 트위스트, 접촉 불량 |
| ESP32 리부팅 반복 | LM2596 출력 전압·전류 확인, USB와 VIN 동시 연결 금지 |
| WiFi는 되는데 느림 | CAN 타임아웃 대기 때문 — 정상, 실차 연결로 해소 |

검증 결과(성공/실패 단계, 로그)는 이 파일에 기록해서 커밋할 것.
